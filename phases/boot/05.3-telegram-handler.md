# Phase 5.3: Telegram Handler (telegram.py)

## Context

RALY's Boot harness is a custom Python process that receives Telegram messages and
delegates Claude Code CLI tasks inside ephemeral Docker containers. `telegram.py` is the
user interface — it receives messages via Telegram polling (no inbound ports), routes them
through the security middleware (Phase 5.1), and dispatches work to the executor (Phase 5.4).

Architecture position:

```
Telegram API (outbound polling, no webhook)
    ↓
telegram.py (this file)
    ├── security.py (@protected decorator on every handler)
    ├── executor.py (send Claude tasks)
    ├── session.py (project context switching)
    └── config.py (bot token, settings)
```

## Implementation Specification

### Bot Initialization

```python
from telegram.ext import Application, CommandHandler, MessageHandler, filters

async def start_bot(config: BootConfig, security: SecurityMiddleware):
    """Initialize and start the Telegram bot with polling.

    Key decisions:
    - Polling mode (NOT webhook): no inbound ports needed, works behind NAT/firewall
    - All handlers wrapped with @security.protected
    - Concurrent updates handled via asyncio queue
    """
    app = Application.builder().token(config.telegram_bot_token).build()

    # Register handlers — ALL wrapped with security
    app.add_handler(CommandHandler("start", protected_start))
    app.add_handler(CommandHandler("new", protected_new))
    app.add_handler(CommandHandler("cd", protected_cd))
    app.add_handler(CommandHandler("ls", protected_ls))
    app.add_handler(CommandHandler("pwd", protected_pwd))
    app.add_handler(CommandHandler("status", protected_status))
    app.add_handler(CommandHandler("export", protected_export))
    app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, protected_message))

    # Start polling
    await app.run_polling(drop_pending_updates=True)
```

### Message Queue

```python
import asyncio

class TaskQueue:
    """Async queue for Claude Code tasks.

    Prevents message drops while Claude is processing.
    Tasks are processed sequentially per project (no concurrent edits to same project).
    Tasks for different projects could theoretically run in parallel, but start with
    sequential for safety.
    """

    def __init__(self, max_depth: int = 20):
        self.queue = asyncio.Queue(maxsize=max_depth)
        self.processing = False

    async def enqueue(self, task):
        """Add task to queue. If full, notify user and drop."""
        try:
            self.queue.put_nowait(task)
        except asyncio.QueueFull:
            # Notify user queue is full
            pass

    async def process_loop(self):
        """Background loop that processes queued tasks."""
        while True:
            task = await self.queue.get()
            self.processing = True
            try:
                result = await execute_task(task)
                await send_result(task, result)
            except Exception as e:
                await send_error(task, e)
            finally:
                self.processing = False
                self.queue.task_done()
```

### Error Handling

- Telegram API errors: log, retry with backoff for transient errors (rate limits, timeouts)
- Claude executor errors: log, send error summary to user
- Unexpected exceptions: log full traceback to audit, send generic error to user
- Never crash the bot on a single message failure — catch, log, continue

### Bot Lifecycle

```python
async def run_bot():
    """Main entry point called by main.py.

    1. Load config
    2. Initialize security middleware
    3. Initialize session manager
    4. Initialize task queue
    5. Start queue processor
    6. Start Telegram polling
    7. Handle shutdown gracefully (save sessions, drain queue)
    """
```

Graceful shutdown:
- On SIGTERM/SIGINT: stop accepting new messages
- Drain the queue (process remaining tasks)
- Save all session state
- Close database connections
- Exit cleanly
