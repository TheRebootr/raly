# Phase 5.5: Session and Memory (session.py, memory.py)

## Context

RALY's Boot harness is a custom Python process that receives Telegram messages and
delegates Claude Code CLI tasks inside ephemeral Docker containers. `session.py` and
`memory.py` manage conversational state — tracking which project is active, maintaining
conversation history per project, and injecting context into Claude Code CLI invocations.

Architecture position:

```
telegram.py
    ├── /cd project → session.py (switch project, resume conversation)
    ├── /new → session.py (clear conversation for current project)
    ├── message → session.py (get context) → executor.py (include context)
    │                                            ↓
    │                                     Claude CLI with context
    │                                            ↓
    └── result → memory.py (save to conversation history)

Data store: ~/BootDrive/data/boot.db (SQLite)
    ├── sessions table (active project per user)
    ├── conversations table (message history per project)
    └── audit_log table (from security.py — shared database)
```

## Implementation Specification

### Database Schema

Both modules share `~/BootDrive/data/boot.db`. The audit_log table is owned by security.py
(Phase 5.1). Session and conversation tables are defined here.

```sql
-- Active session per user (which project they're working on)
CREATE TABLE IF NOT EXISTS sessions (
    user_id INTEGER PRIMARY KEY,
    project_dir TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%f', 'now'))
);

-- Conversation history per project
CREATE TABLE IF NOT EXISTS conversations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_dir TEXT NOT NULL,
    role TEXT NOT NULL,        -- 'user' or 'assistant'
    content TEXT NOT NULL,
    timestamp TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%f', 'now')),
    metadata TEXT              -- JSON: token count, duration, etc.
);

CREATE INDEX IF NOT EXISTS idx_conv_project ON conversations(project_dir);
CREATE INDEX IF NOT EXISTS idx_conv_timestamp ON conversations(timestamp);
```

```python
class SessionManager:
    """Manages active project sessions per user.

    Each user has exactly one active project at a time.
    Switching projects (/cd) saves the current project and loads the new one.
    The session persists across bot restarts (SQLite-backed).
    """

    def __init__(self, db_path: Path):
        self.db_path = db_path

    async def initialize(self):
        """Create tables if they don't exist. Called once at startup."""

    async def get_current_project(self, user_id: int) -> str | None:
        """Return the active project directory for this user, or None."""

    async def set_current_project(self, user_id: int, project_dir: str):
        """Set the active project directory for this user.

        Validates:
        - project_dir exists within workspace
        - project_dir is a directory (not a file)
        - No path traversal
        """

    async def get_default_project(self) -> str:
        """Return 'scratch' as the default project.
        Create ~/BootDrive/workspace/scratch/ if it doesn't exist."""
```

Implementation requirements:
- Session is per-user (keyed by Telegram user ID)
- Only one active project at a time per user
- Persists across restarts (SQLite)
- Default to `scratch` if no project selected
- Create `scratch` directory if it doesn't exist
- Validate project directory exists before switching

### memory.py — Conversation Memory

```python
class ConversationMemory:
    """Manages conversation history per project.

    History is keyed by project directory. When the user switches projects
    with /cd, the previous project's history is preserved and the target
    project's history is loaded.

    History is used to inject context into Claude Code CLI invocations,
    enabling multi-turn conversations within a project.
    """

    def __init__(self, db_path: Path, max_history: int = 50):
        self.db_path = db_path
        self.max_history = max_history  # Max messages to retain per project

    async def initialize(self):
        """Create tables if they don't exist."""

    async def add_message(self, project_dir: str, role: str, content: str,
                          metadata: dict = None):
        """Add a message to the project's conversation history.

        Args:
            project_dir: The project this message belongs to
            role: 'user' or 'assistant'
            content: Message text
            metadata: Optional dict (token count, duration, cost, etc.)
        """

    async def get_history(self, project_dir: str, limit: int = None) -> list[dict]:
        """Get recent conversation history for a project.

        Returns list of {role, content, timestamp} ordered oldest-first.
        Limit defaults to self.max_history.
        """

    async def clear_history(self, project_dir: str):
        """Clear conversation history for a project (/new command)."""

    async def get_context_for_claude(self, project_dir: str) -> str:
        """Format recent history as context string for Claude Code CLI.

        Returns a formatted string that can be prepended to the user's message
        to give Claude context about the conversation so far.

        Format:
        Previous conversation in this project:
        ---
        User: <message>
        Assistant: <response>
        User: <message>
        Assistant: <response>
        ---
        Current request:
        """

    async def export_history(self, project_dir: str) -> str:
        """Export full conversation history as markdown for /export command."""
```

Implementation requirements:

#### History Management
- Append-only during operation
- When history exceeds `max_history` (default 50), prune oldest messages
- Pruning is soft: mark as archived, don't delete (can be recovered)
- Or simpler: just keep last N, delete older ones (less complexity)

#### Context Injection
- `get_context_for_claude()` returns a string prepended to the user's message
- Include last 10 messages (configurable) as context
- Truncate individual messages in context if they're too long (>1000 chars each)
- Total context string should not exceed ~4000 chars to leave room for the actual prompt

#### CLAUDE.md Integration
```python
async def get_project_claude_md(self, project_dir: str, workspace_dir: Path) -> str:
    """Read the project's CLAUDE.md file if it exists.

    Looks for CLAUDE.md in the project directory within the workspace.
    This provides persistent, editable project-specific instructions.
    """
    claude_md_path = workspace_dir / project_dir / "CLAUDE.md"
    if claude_md_path.exists():
        return claude_md_path.read_text()
    return ""
```

- Each project directory can have its own CLAUDE.md
- CLAUDE.md content is injected alongside conversation history
- CLAUDE.md is editable by the user (it's in the workspace)
- A global CLAUDE.md in `~/BootDrive/app/` defines Boot's base personality

#### Export Format
```markdown
# Conversation Export: project-name
## Date: 2025-01-15

### User (14:30:00)
Message text here

### Assistant (14:30:45)
Response text here

---
```

### Database Connection Management

```python
import aiosqlite

class Database:
    """Shared async database connection manager.

    Used by SessionManager, ConversationMemory, and AuditLogger.
    All share the same SQLite file but manage their own tables.
    """

    def __init__(self, db_path: Path):
        self.db_path = db_path
        self._conn: aiosqlite.Connection = None

    async def connect(self):
        """Open connection. Enable WAL mode for concurrent reads."""
        self._conn = await aiosqlite.connect(str(self.db_path))
        await self._conn.execute("PRAGMA journal_mode=WAL")
        await self._conn.execute("PRAGMA foreign_keys=ON")

    async def close(self):
        """Close connection gracefully."""
        if self._conn:
            await self._conn.close()

    @property
    def conn(self) -> aiosqlite.Connection:
        if self._conn is None:
            raise RuntimeError("Database not connected. Call connect() first.")
        return self._conn
```

WAL mode enables concurrent reads while writing, which is important since the audit
logger writes frequently while the session manager reads.
