# Phase 5.1: Security Module (security.py)

## Context

RALY's Boot harness is a custom Python process that receives Telegram messages and
delegates Claude Code CLI tasks inside ephemeral Docker containers. `security.py` is the
front door — nothing reaches Claude without passing through it. This is THE MOST IMPORTANT
FILE in the entire harness. Build it first, test it independently, and treat any bypass
as a critical defect.

Architecture position:

```
Telegram message → telegram.py → security.py → executor.py → Docker sandbox
                                  ↑ THIS FILE
                                  Responsibilities:
                                  1. Auth (Telegram ID allowlist)
                                  2. Rate limiting (token bucket)
                                  3. Input validation (path traversal, injection)
                                  4. Audit logging (SQLite, every action)
```

## Implementation Specification

### Component 1: Auth Middleware

```python
# Core concept: decorator that wraps EVERY Telegram handler
# MUST be the absolute first check in every handler
# Pattern: extracted from RichardAtCT's auth middleware

def authorized_only(handler):
    """Decorator: rejects any Telegram update not from an allowed user ID.

    - Checks update.effective_user.id against allowlist
    - Allowlist loaded from config.env TELEGRAM_ALLOWED_USERS (comma-separated IDs)
    - Rejected requests: logged to audit, NO response sent (silent drop)
    - Silent drop is intentional: don't confirm the bot exists to unauthorized users
    """
```

Implementation requirements:
- Allowlist is a `set[int]` loaded once at startup from config
- Check is `O(1)` — set lookup
- Rejected requests are logged with: timestamp, user_id, username, message text
- NO response is sent to unauthorized users (silent drop)
- No exceptions, no bypass, no "check later" — this wraps the handler itself

### Component 2: Rate Limiter

```python
# Dual token bucket: one for request count, one for estimated API cost
# Prevents: spam, runaway API bills, accidental loops

class RateLimiter:
    """Dual-bucket token bucket rate limiter.

    Bucket 1 (requests): limits raw request count per time window
    Bucket 2 (cost): limits estimated API cost per time window

    Both must pass for a request to proceed.
    When either bucket is exhausted, the request is queued (not dropped).
    User receives a "rate limited, will process shortly" message.
    """
```

Implementation requirements:
- Request bucket: configurable max requests per minute (default 10)
- Cost bucket: configurable max estimated cost per hour (default 100 units)
- Token refill is continuous (not fixed-window)
- When rate limited: user gets a brief notification, request is queued
- Queue has a max depth (e.g., 20) — beyond that, requests ARE dropped with notification
- Rate limiter state is per-user (even though we have one user, design for correctness)
- Cost estimation: simple heuristic based on message length (exact cost is unknown pre-execution)

### Component 3: Input Validator

```python
class InputValidator:
    """Validates and sanitizes user input before it reaches the executor.

    Defense in depth: Docker sandboxing is the primary containment boundary.
    Input validation is a secondary layer that catches obvious attacks before
    they even reach the sandbox.
    """
```

Implementation requirements:

#### Path Traversal Prevention
- Normalize all paths using `pathlib.Path.resolve()`
- Reject any path containing `..` after normalization
- Reject any absolute path — all paths must be relative to the workspace
- Validate that resolved path stays within `BOOT_WORKSPACE`

#### Command Injection Sanitization
- For `/cd`, `/ls` commands: validate against allowed characters (alphanumeric, `-`, `_`, `.`, `/`)
- For free-text messages to Claude: pass through (Claude CLI handles its own input)
- Reject messages containing shell metacharacters in command arguments: `;`, `|`, `&`, `$`, `` ` ``, `\n`

#### Size Limits
- Maximum message length: 4096 characters (Telegram's own limit)
- Maximum file upload size: 20MB (Telegram's limit)
- Reject messages that are unreasonably long for their command type

#### Content Policy
- Log but do not filter free-text messages to Claude (that's Claude's job)
- Only validate structural/command inputs

### Component 4: Audit Logger

```python
class AuditLogger:
    """SQLite-based audit trail. Every action is logged. No exceptions.

    This is the flight recorder. If something goes wrong, this is how you
    find out what happened.
    """
```

Implementation requirements:

#### Schema

```sql
CREATE TABLE IF NOT EXISTS audit_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%f', 'now')),
    user_id INTEGER,
    username TEXT,
    action TEXT NOT NULL,  -- 'auth_ok', 'auth_rejected', 'rate_limited',
                           -- 'input_rejected', 'task_started', 'task_completed',
                           -- 'task_failed', 'command', 'error'
    detail TEXT,           -- JSON blob with action-specific data
    source_ip TEXT,        -- from Telegram update if available
    result TEXT            -- 'success', 'failure', 'queued', 'dropped'
);

CREATE INDEX IF NOT EXISTS idx_audit_timestamp ON audit_log(timestamp);
CREATE INDEX IF NOT EXISTS idx_audit_user_id ON audit_log(user_id);
CREATE INDEX IF NOT EXISTS idx_audit_action ON audit_log(action);
```

#### Logging Requirements
- Every auth check (pass and fail)
- Every rate limit check (pass and throttle)
- Every input validation (pass and reject)
- Every Claude task start, completion, and failure
- Every command invocation (/cd, /ls, /pwd, etc.)
- Every error with full traceback
- Structured detail field (JSON) — queryable, not just free text

#### Rotation
- Audit log is append-only during operation
- Implement log rotation: archive logs older than 30 days to compressed files
- Or rely on SQLite's ability to handle large tables and just add cleanup queries

#### Query Interface
- Provide a method to query recent entries (for /status command in telegram.py)
- Provide a method to export (for incident response)

### Integration: SecurityMiddleware

```python
class SecurityMiddleware:
    """Combines all security components into a single middleware layer.

    Usage in telegram.py:
        security = SecurityMiddleware(config)

        @security.protected
        async def handle_message(update, context):
            # If we get here: auth passed, rate limit passed, input validated
            # Audit log already has the entry
            ...
    """
```

This class:
1. Holds instances of RateLimiter, InputValidator, AuditLogger
2. Provides `@protected` decorator that chains: auth → rate_limit → validate → audit → handler
3. Exposes `audit` method for other modules to log events (executor logs task results)
4. Exposes `check_rate` method for cost tracking (executor reports actual cost post-task)
