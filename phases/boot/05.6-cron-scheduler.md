# Phase 5.6: Cron / Scheduled Tasks (systemd timers)

## Context

RALY's Boot harness is a custom Python process (systemd service: `boot.service`)
that receives Telegram messages and delegates Claude Code CLI tasks. This phase adds
scheduled automation — recurring tasks triggered by systemd timers that invoke Boot
actions (health checks, test runs, dependency audits). Scheduling is done via systemd
timers, NOT in-process schedulers, for separation of concerns and reliability.

Architecture position:

```
systemd timers (OS-level scheduling)
    ↓ triggers
systemd oneshot services
    ↓ invokes either:
    Option A: Telegram API (send message to Bot → Bot processes normally)
    Option B: Direct executor script (bypass Telegram, use executor.py directly)
```

## Prerequisites

- Phase 5.3 complete: Telegram bot running as `boot.service`
- Phase 5.4 complete: `executor.py` can run Claude tasks
- Boot service is running and responsive
- systemd access (standard on Omarchy/Arch)

## File Locations

- `/etc/systemd/system/boot-*.timer` — Timer unit files
- `/etc/systemd/system/boot-*.service` — Corresponding oneshot services
- `~/boot-src/scripts/` — Helper scripts invoked by timers

## Implementation Specification

### Design Decision: systemd Timers vs In-Process Scheduling

Use systemd timers (not Python `schedule`, `APScheduler`, or `asyncio` loops) because:
- Survives bot process crashes (timer keeps ticking independently)
- Managed by the OS scheduler (proven, reliable)
- Visible in `systemctl list-timers` (observable)
- Logs integrated with journald (queryable)
- No additional Python dependencies

### Prerequisite: boot.service Unit File

Before timers, create the main Boot service unit. This is Boot's systemd lifecycle.

Create `/etc/systemd/system/boot.service`:

```ini
[Unit]
Description=Boot - RALY Claude Code Telegram Harness
After=network-online.target docker.service
Wants=network-online.target
Requires=docker.service

[Service]
Type=simple
User=<your-username>
Group=<your-group>
WorkingDirectory=/home/<your-username>/boot-src
ExecStart=/home/<your-username>/boot-src/venv/bin/python -m boot.main
Restart=on-failure
RestartSec=10
StartLimitBurst=5
StartLimitIntervalSec=60

# Security hardening for the service itself
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/home/<your-username>/boot-data
ReadWritePaths=/home/<your-username>/boot-workspace

# Environment
EnvironmentFile=/home/<your-username>/boot-data/config.env

# Logging
StandardOutput=journal
StandardError=journal
SyslogIdentifier=boot

[Install]
WantedBy=multi-user.target
```

Enable and start:

```bash
sudo systemctl daemon-reload
sudo systemctl enable boot.service
sudo systemctl start boot.service
sudo systemctl status boot.service
```

### main.py Entry Point

Create `~/boot-src/boot/main.py`:

```python
"""Boot harness entry point. Launched by systemd."""

import asyncio
import signal
import logging
from boot.config import load_config
from boot.security import SecurityMiddleware
from boot.telegram import run_bot

logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s [%(name)s] %(levelname)s: %(message)s'
)

def main():
    config = load_config()
    # run_bot handles the rest: security init, session init, polling start
    asyncio.run(run_bot(config))

if __name__ == "__main__":
    main()
```

### Timer 1: Health Check (every 6 hours)

Purpose: Verify Boot is responsive and system health is good.

Create `~/boot-src/scripts/health-check.sh`:

```bash
#!/bin/bash
# Health check: verify Boot is responsive and system is healthy
set -euo pipefail

LOG_DIR="/home/<your-username>/boot-data/logs"
TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')

echo "[$TIMESTAMP] Health check starting" >> "$LOG_DIR/health.log"

# Check 1: boot.service is running
if ! systemctl is-active --quiet boot.service; then
    echo "[$TIMESTAMP] ALERT: boot.service is not running" >> "$LOG_DIR/health.log"
    # Optionally send alert via Telegram API directly:
    # curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
    #   -d "chat_id=${TELEGRAM_ALLOWED_USERS}" \
    #   -d "text=ALERT: boot.service is down"
    exit 1
fi

# Check 2: Disk space
DISK_PCT=$(df /home | tail -1 | awk '{print $5}' | sed 's/%//')
if [ "$DISK_PCT" -gt 90 ]; then
    echo "[$TIMESTAMP] WARNING: Disk usage at ${DISK_PCT}%" >> "$LOG_DIR/health.log"
fi

# Check 3: Docker daemon
if ! docker info > /dev/null 2>&1; then
    echo "[$TIMESTAMP] ALERT: Docker daemon is not running" >> "$LOG_DIR/health.log"
    exit 1
fi

# Check 4: Database integrity
DB_PATH="/home/<your-username>/boot-data/boot.db"
if [ -f "$DB_PATH" ]; then
    INTEGRITY=$(sqlite3 "$DB_PATH" "PRAGMA integrity_check;" 2>/dev/null)
    if [ "$INTEGRITY" != "ok" ]; then
        echo "[$TIMESTAMP] ALERT: Database integrity check failed" >> "$LOG_DIR/health.log"
    fi
fi

echo "[$TIMESTAMP] Health check passed" >> "$LOG_DIR/health.log"
```

```bash
chmod +x ~/boot-src/scripts/health-check.sh
```

Create `/etc/systemd/system/boot-health.service`:

```ini
[Unit]
Description=Boot Health Check

[Service]
Type=oneshot
User=<your-username>
ExecStart=/home/<your-username>/boot-src/scripts/health-check.sh
EnvironmentFile=/home/<your-username>/boot-data/config.env
```

Create `/etc/systemd/system/boot-health.timer`:

```ini
[Unit]
Description=Boot Health Check Timer

[Timer]
OnCalendar=*-*-* 00/6:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable boot-health.timer
sudo systemctl start boot-health.timer
```

### Timer 2: Log Rotation (daily)

Purpose: Rotate and compress old logs to prevent disk fill.

Create `~/boot-src/scripts/log-rotate.sh`:

```bash
#!/bin/bash
# Rotate Boot logs older than 30 days
set -euo pipefail

LOG_DIR="/home/<your-username>/boot-data/logs"
TIMESTAMP=$(date '+%Y-%m-%d')

# Compress logs older than 7 days
find "$LOG_DIR" -name "*.log" -mtime +7 -exec gzip {} \;

# Delete compressed logs older than 30 days
find "$LOG_DIR" -name "*.log.gz" -mtime +30 -delete

# Rotate audit log entries older than 30 days
DB_PATH="/home/<your-username>/boot-data/boot.db"
if [ -f "$DB_PATH" ]; then
    sqlite3 "$DB_PATH" "DELETE FROM audit_log WHERE timestamp < datetime('now', '-30 days');"
    sqlite3 "$DB_PATH" "VACUUM;"
fi

echo "[$TIMESTAMP] Log rotation complete" >> "$LOG_DIR/rotation.log"
```

```bash
chmod +x ~/boot-src/scripts/log-rotate.sh
```

Create corresponding `.service` and `.timer` files following the same pattern as
the health check, with `OnCalendar=daily`.

### Timer 3: Docker Cleanup (weekly)

Purpose: Remove dangling images, stopped containers, unused networks.

Create `~/boot-src/scripts/docker-cleanup.sh`:

```bash
#!/bin/bash
# Clean up Docker artifacts
set -euo pipefail

docker system prune -f --filter "until=72h"
docker image prune -f --filter "until=168h"
```

Create corresponding `.service` and `.timer` files with `OnCalendar=weekly`.

### Timer 4: Dependency Audit (monthly, optional)

Purpose: Check Boot's Python dependencies for known vulnerabilities.

Create `~/boot-src/scripts/dep-audit.sh`:

```bash
#!/bin/bash
# Audit Python dependencies for CVEs
set -euo pipefail

VENV="/home/<your-username>/boot-src/venv"
LOG="/home/<your-username>/boot-data/logs/dep-audit.log"

source "$VENV/bin/activate"
pip audit 2>&1 | tee -a "$LOG"
```

Create corresponding `.service` and `.timer` files with `OnCalendar=monthly`.

### Adding Custom Scheduled Claude Tasks

For user-defined scheduled Claude tasks (e.g., "run tests every night"), create
a script template:

```bash
#!/bin/bash
# Scheduled Claude task template
# Sends a message to Boot via Telegram API, which processes it
# through the normal security pipeline

TOKEN="${TELEGRAM_BOT_TOKEN}"
CHAT_ID="${TELEGRAM_ALLOWED_USERS}"
MESSAGE="Run all tests in project-a and report results"

curl -s "https://api.telegram.org/bot${TOKEN}/sendMessage" \
    -d "chat_id=${CHAT_ID}" \
    -d "text=${MESSAGE}"
```

This approach routes scheduled tasks through the same security pipeline as
interactive messages. The bot sees them as regular messages from the Telegram API.
