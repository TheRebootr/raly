# Phase 5.4: Claude Executor (executor.py)

## Context

Boot lives inside a single long-lived Docker container (Debian Bookworm) with full
network access. Claude Code CLI is installed in the container image and runs as a
**subprocess** — no sub-containers, no Docker-in-Docker, no Docker socket.

The container boundary (Phase 2) provides all isolation: read-only rootfs, cap-drop ALL,
no-new-privileges, noexec tmpfs, resource limits. The executor's job is simple: run
`claude` as a child process, capture output, enforce timeouts, log results.

Architecture position:

```
telegram.py (message handler)
    ↓ task: (project_dir, message_text)
executor.py (this file)
    ↓ spawns subprocess (NOT a Docker container)
    asyncio.create_subprocess_exec(
        "claude", "--print", "--output-format", "text",
        message_text,
        cwd="/workspace/<project>"
    )
    ↓ captures stdout/stderr
executor.py
    ↓ result: (output_text, exit_code, duration, cost_estimate)
telegram.py (sends response to user)
```

Key simplification from old design: The executor is ~100 lines, not ~300. No
DockerCommandBuilder, no sandbox image, no `--network none` conflict. Claude runs
directly inside Boot's container, which already has full network access for API calls.

## Implementation Specification

### Task Data Structure

```python
from dataclasses import dataclass

@dataclass
class Task:
    """A unit of work for Claude Code execution."""
    project_dir: str         # Subdirectory name within workspace (e.g., "project-a")
    message: str             # The user's message/prompt for Claude
    chat_id: int             # Telegram chat ID for response routing
    user_id: int             # Telegram user ID (for audit)
    session_context: str     # Previous conversation context (from session.py)

@dataclass
class TaskResult:
    """Result from Claude Code execution."""
    output: str              # Claude's response text
    exit_code: int           # Process exit code (0 = success)
    duration_seconds: float  # Wall clock time
    cost_estimate: float     # Estimated API cost units (for rate limiter)
    error: str = ""          # Error message if failed
    truncated: bool = False  # Whether output was truncated
```

### Executor

```python
class ClaudeExecutor:
    """Executes Claude Code CLI tasks as subprocesses.

    Claude runs directly inside Boot's container. The container already
    provides all isolation (Phase 2). This class just manages the process
    lifecycle: spawn, timeout, capture, log.

    ~100 lines of real logic.
    """

    def __init__(self, config: BootConfig, audit: AuditLogger):
        self.config = config
        self.audit = audit

    async def execute(self, task: Task) -> TaskResult:
        """Execute a Claude Code task as a subprocess.

        Flow:
        1. Validate project directory exists and is within workspace
        2. Log task_started to audit
        3. Spawn subprocess with timeout
        4. Capture stdout/stderr
        5. Log task_completed or task_failed to audit
        6. Return TaskResult
        """
```

Implementation requirements:

#### Project Directory Validation
- Verify `config.workspace_dir / task.project_dir` exists and is a directory
- Resolve the path and verify it stays within `config.workspace_dir` (no symlink escape)
- If not: return TaskResult with error, do not spawn process

```python
def _validate_project_dir(self, project_dir: str) -> Path | None:
    """Validate and resolve project directory. Returns None if invalid."""
    workspace = self.config.workspace_dir.resolve()
    target = (workspace / project_dir).resolve()

    # Must be within workspace (prevents ../../../etc/passwd)
    if not str(target).startswith(str(workspace)):
        return None

    if not target.is_dir():
        return None

    return target
```

#### Command Building

```python
def _build_command(self, task: Task) -> list[str]:
    """Build the claude CLI command.

    Simple: just claude with --print flag for non-interactive mode.
    No Docker commands, no security flags — the container handles all of that.
    """
    return [
        "claude",
        "--print",              # Non-interactive, single-shot mode
        "--output-format", "text",  # Plain text output (not JSON)
        task.message,
    ]
```

**Why no security flags here:** The executor doesn't need `--network none`,
`--cap-drop ALL`, `--read-only`, etc. Those are properties of the **container**
(Phase 2), not the subprocess. Claude runs inside a container that already has all
these constraints applied.

#### Subprocess Management

```python
async def _run_claude(self, cmd: list[str], cwd: Path, timeout: int) -> tuple[str, str, int]:
    """Run Claude CLI as async subprocess with timeout enforcement."""
    proc = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
        cwd=str(cwd),
    )

    try:
        stdout, stderr = await asyncio.wait_for(
            proc.communicate(),
            timeout=timeout,
        )
        return stdout.decode(), stderr.decode(), proc.returncode
    except asyncio.TimeoutError:
        proc.kill()
        await proc.wait()
        return "", "Task timed out", -1
```

#### Output Handling
- Max output size: 50KB (Claude responses can be long)
- If output exceeds 50KB: truncate and set `truncated=True`
- Clean output: strip ANSI escape codes
- No Docker overhead to strip (unlike old architecture — it's a direct subprocess)

#### Error Handling and Retry

```python
async def execute_with_retry(self, task: Task, max_retries: int = 2) -> TaskResult:
    """Execute with retry logic for transient failures.

    Retry on:
    - Timeout (with backoff)
    - Claude CLI crash (non-zero exit, non-auth related)

    Do NOT retry on:
    - Auth failures (exit code specific to auth)
    - Invalid project directory
    - Claude API errors with specific error messages (likely permanent)
    """
```

- Retry with exponential backoff: 2s, 4s
- Max 2 retries (3 total attempts)
- Only retry transient failures
- Log each retry attempt to audit

#### Cost Estimation

```python
def estimate_cost(self, message_length: int, output_length: int) -> float:
    """Rough cost estimation for rate limiter feedback.

    This doesn't need to be precise — it's for rate limiting, not billing.
    Claude Code CLI doesn't expose token counts directly, so estimate:
    - Input tokens ≈ message_length / 4
    - Output tokens ≈ output_length / 4
    - Cost units = (input_tokens + output_tokens * 3) / 1000
    """
```

### Claude CLI Authentication

Claude Code CLI runs inside Boot's container, which has full network access.
Authentication options:

**Option A: `ANTHROPIC_API_KEY` environment variable (recommended)**
- Set in the container's environment via systemd unit or config
- The key lives in `~/boot-data/config.env` (mounted volume, accepted blast radius)
- The container has network, so the key could theoretically be exfiltrated — but this
  is accepted since the container boundary IS the trust boundary
- No need for the old `--network none` workaround — the container has network by design

**Option B: `claude auth login` once inside the container**
- Interactive login, credentials stored in `~/.claude/` inside the container
- With `--read-only` rootfs, this needs `/home/node` tmpfs — which means re-auth
  on every container restart
- Less suitable for headless operation

**Recommended:** Option A. Set `ANTHROPIC_API_KEY` in the systemd unit's environment
or read it from the config file at startup.

### Process Cleanup

Unlike the old architecture, there are no orphaned Docker containers to clean up.
Claude runs as a subprocess — when killed, it's gone. The only cleanup needed:

```python
async def cancel_running_task(self):
    """Cancel the currently running Claude process, if any.

    Called when:
    - User sends /cancel command
    - Container is shutting down (SIGTERM handler)
    """
    if self._current_proc and self._current_proc.returncode is None:
        self._current_proc.kill()
        await self._current_proc.wait()
```

## What Changed from the Old Design

| Old (Phase 5.4 v1)                           | New (this version)                              |
| --------------------------------------------- | ----------------------------------------------- |
| `DockerCommandBuilder` class (~200 lines)     | `_build_command()` method (~5 lines)            |
| `docker run --rm --network none ...`          | `claude --print ...` as subprocess              |
| Ephemeral per-task Docker containers          | Direct subprocess inside Boot's container       |
| Needed Docker socket access from Boot         | No Docker access needed                         |
| `boot-sandbox:latest` separate image          | Uses Boot's own container image                 |
| `--network none` conflicting with API access  | Container has network by design (Phase 2)       |
| Container cleanup for orphaned containers     | Process cleanup (just kill the subprocess)       |
| ~300 lines of executor code                   | ~100 lines of executor code                     |
