# Phase 5.4: Claude Executor (executor.py)

## Context

RALY's Boot harness is a custom Python process that receives Telegram messages and
delegates Claude Code CLI tasks inside ephemeral Docker containers. `executor.py` is the
execution engine — it takes a validated task (message text + project directory), spawns a
Docker container with Claude Code CLI, captures output, and returns results.

Architecture position:

```
telegram.py (task queue)
    ↓ task: (project_dir, message_text)
executor.py (this file)
    ↓ spawns
docker run --rm --network none --read-only \
    --memory 2g --cpus 2 --pids-limit 256 \
    --cap-drop ALL --security-opt no-new-privileges:true \
    -u 1000:1000 \
    -v ~/boot-workspace/<project>:/workspace:rw \
    boot-sandbox:latest \
    claude --print "<message_text>"
    ↓ captures stdout/stderr
executor.py
    ↓ result: (output_text, exit_code, duration, cost_estimate)
telegram.py (sends response to user)
```

Key design decision: Claude Code CLI is invoked via `subprocess` → `docker run`, NOT via
an in-process SDK. This provides a natural process boundary. The Docker container is
ephemeral (destroyed after each task), air-gapped (`--network none`), and resource-limited.

### Docker Command Builder

```python
class DockerCommandBuilder:
    """Builds the docker run command with all security constraints.

    Every container is:
    - Ephemeral (--rm)
    - Network isolated (--network none)
    - Read-only root filesystem (--read-only)
    - Resource limited (memory, CPU, pids)
    - Privilege restricted (no-new-privileges, cap-drop ALL)
    - Non-root user (1000:1000)
    - Mount restricted (only the active project directory)
    """

    def build(self, config: BootConfig, task: Task) -> list[str]:
        """Build docker run command as argument list.

        Returns a list suitable for asyncio.create_subprocess_exec().
        """
        workspace_path = config.workspace_dir / task.project_dir

        return [
            "docker", "run",
            "--rm",                                    # Destroy after task
            "--network", "none",                       # No network access
            "--read-only",                             # Immutable root FS
            f"--memory={config.docker_memory_limit}",  # e.g., 2g
            f"--cpus={config.docker_cpu_limit}",       # e.g., 2
            f"--pids-limit={config.docker_pids_limit}",# e.g., 256
            "--security-opt", "no-new-privileges:true",
            "--cap-drop", "ALL",
            "--user", "1000:1000",
            "--tmpfs", "/tmp:rw,noexec,nosuid,size=256m",  # Writable /tmp for Claude
            "-v", f"{workspace_path}:/workspace:rw",   # Only this project
            "-w", "/workspace",                        # Working directory
            "-e", "HOME=/home/claude",                 # Set home for Claude CLI
            config.sandbox_image,                      # boot-sandbox:latest
            "claude", "--print", task.message,         # Claude Code CLI invocation
        ]
```

**Critical security notes on the command:**
- `--network none`: No internet, no DNS, no communication with host network
- `--read-only`: Root filesystem is immutable, only `/workspace` and `/tmp` are writable
- `--cap-drop ALL`: Removes ALL Linux capabilities
- `--security-opt no-new-privileges:true`: Prevents privilege escalation via setuid
- `-v` mounts ONLY the specific project directory, not the entire workspace
- `--tmpfs /tmp`: Claude CLI may need a writable temp directory, but it's memory-only
  and noexec
- `--user 1000:1000`: Non-root user inside container

### Executor

```python
class ClaudeExecutor:
    """Executes Claude Code CLI tasks in Docker sandboxes.

    Responsibilities:
    - Build Docker command
    - Spawn subprocess
    - Enforce timeout
    - Capture output
    - Handle errors and retries
    - Log task lifecycle to audit
    """

    def __init__(self, config: BootConfig, audit: AuditLogger):
        self.config = config
        self.audit = audit
        self.cmd_builder = DockerCommandBuilder()

    async def execute(self, task: Task) -> TaskResult:
        """Execute a Claude Code task in a sandboxed container.

        Flow:
        1. Validate project directory exists
        2. Build Docker command
        3. Log task_started to audit
        4. Spawn subprocess with timeout
        5. Capture stdout/stderr
        6. Log task_completed or task_failed to audit
        7. Return TaskResult
        """
```

Implementation requirements:

#### Project Directory Validation
- Verify `config.workspace_dir / task.project_dir` exists and is a directory
- Verify it resolves within `config.workspace_dir` (no symlink escape)
- If not: return TaskResult with error, do not spawn container

#### Subprocess Management
```python
async def _run_container(self, cmd: list[str], timeout: int) -> tuple[str, str, int]:
    """Run Docker container as async subprocess with timeout enforcement.

    Uses asyncio.create_subprocess_exec() for non-blocking execution.
    """
    proc = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )

    try:
        stdout, stderr = await asyncio.wait_for(
            proc.communicate(),
            timeout=timeout,
        )
        return stdout.decode(), stderr.decode(), proc.returncode
    except asyncio.TimeoutError:
        # Kill the subprocess (which kills the Docker container)
        proc.kill()
        await proc.wait()
        # Also force-remove the container in case kill didn't clean up
        # (--rm should handle this, but belt and suspenders)
        return "", "Task timed out", -1
```

#### Output Handling
- Max output size: 50KB (Claude responses can be long)
- If output exceeds 50KB: truncate and set `truncated=True`
- Parse output for cost estimation (look for token usage in stderr if available)
- Clean output: strip ANSI escape codes, strip Docker overhead

#### Error Handling and Retry

```python
async def execute_with_retry(self, task: Task, max_retries: int = 2) -> TaskResult:
    """Execute with retry logic for transient failures.

    Retry on:
    - Docker daemon errors (container creation failed)
    - Timeout (with backoff)

    Do NOT retry on:
    - Auth failures
    - Invalid project directory
    - Claude API errors (likely permanent for the same input)
    """
```

- Retry with exponential backoff: 2s, 4s
- Max 2 retries (3 total attempts)
- Only retry transient infrastructure failures
- Log each retry attempt to audit

#### Cost Estimation

```python
def estimate_cost(self, message_length: int, output_length: int) -> float:
    """Rough cost estimation for rate limiter feedback.

    This doesn't need to be precise — it's for rate limiting, not billing.
    Claude Code CLI doesn't expose token counts directly, so estimate:
    - Input tokens ≈ message_length / 4
    - Output tokens ≈ output_length / 4
    - Cost units = (input_tokens + output_tokens * 3) / 1000
    """
```

### Claude CLI Authentication

The Docker container needs Claude Code CLI to be authenticated. Options:

**Option A: Pass credentials via environment variable**
- Mount a credential file or pass an API key via `-e` flag
- Risk: credentials accessible inside container (mitigated by network:none)

**Option B: Pre-authenticate in the sandbox image**
- Bake credentials into the Docker image
- Risk: credentials in image layers (bad practice)

**Option C: Use --print mode with piped input**
- Claude CLI's `--print` flag may work with API key passed at runtime
- Pass `ANTHROPIC_API_KEY` via `-e` flag only when needed

**Recommended: Option A with API key**
- `-e ANTHROPIC_API_KEY=<key>` passed at runtime
- The container has `--network none` so the key can't be exfiltrated over network
- The container is `--rm` so it's destroyed immediately
- The key is in memory only, never written to disk inside the container

**Wait — `--network none` conflicts with API access:**
Claude Code CLI needs to reach the Anthropic API. With `--network none`, it can't.

**Resolution options:**
1. **Run Claude CLI on host, not in container** — simplest, but less isolated
2. **Use restricted networking** — allow only Anthropic API endpoints
3. **Use Claude Code's built-in sandbox** — may handle this internally
4. **Proxy through host** — container talks to host proxy that forwards to API

**Decision required:** This is an open architectural question from the spec. The subagent
implementing this phase MUST resolve it. Research:
- Does Claude Code CLI support offline/cached mode?
- Does `claude --print` work with a local model or require API access?
- Can we use `--network` with a restricted Docker network that only allows Anthropic IPs?
- Can Claude Code's built-in `/sandbox` mode be used instead of (or alongside) Docker?

Document the decision in `~/boot-src/ARCHITECTURE-DECISIONS.md`.

### Container Cleanup

```python
async def cleanup_orphaned_containers(self):
    """Clean up any boot-sandbox containers that survived --rm.

    Safety net: runs periodically to catch containers that weren't cleaned up.
    This should never happen with --rm, but defense in depth.
    """
    proc = await asyncio.create_subprocess_exec(
        "docker", "ps", "-q", "--filter", f"ancestor={self.config.sandbox_image}",
        stdout=asyncio.subprocess.PIPE,
    )
    stdout, _ = await proc.communicate()
    if stdout.strip():
        container_ids = stdout.decode().strip().split('\n')
        for cid in container_ids:
            await asyncio.create_subprocess_exec("docker", "kill", cid)
```
